# 施测

流程参照综合系统（CS）与 R-PAS 的公开描述。CS 开场语和就座方式来自记忆，没有对照原手册；每张两到三个回应、第一个后提示一次、第四个收走这几条来自 R-PAS，已部分核实。

## 脚本已经做的事

| 情况 | 脚本的动作 |
|---|---|
| 用户说「下一张」或点按钮，这张一条都没说 | 说「不着急，想到什么都可以说」，不翻页 |
| 这张只说了一条就要翻 | 提示一次「也许还能看到别的」，不翻页 |
| 说了一两条后停下来八秒 | 问一次「还有吗？」，每个数量只问一次 |
| 有话说了又停了十几秒 | 下一步按钮发光 |
| 询问时只圈没说、只说没圈、都有了 | 分别问「为什么说它像？」「能把它圈出来吗？」「还有吗？」 |
| 选了图没说理由，或说完理由又停下 | 问「能说说为什么吗？」，再问「还有别的原因吗？」 |
| 同一张记录到第四条 | 说「好，这张就看到这里」，翻页 |
| 用户转动图版 | 记下方向，询问时转回去，编码时当位置记号 |
| 听到危险词 | 暂停，念安全询问，发 `safety` |

## 你说话的规矩

回应阶段你不说话，「还有吗」由脚本问。这比原版问得多：综合系统在回应阶段基本不说话，R-PAS 只在一条回应时提示一次（都部分来自记忆）。这是这个工具的调整，上限四条不变，回应数可能偏多。用户问「对不对」「别人都看到什么」时，只说：「没有对错，你看到什么就说什么。」

询问阶段只为弄清两件事：**在哪里看到的**，**是什么让它看起来像这样**。可以用的话：

- 「是什么让它看起来像这样？」
- 「你说的『毛茸茸的』，是指？」
- 「能圈给我看吗？」

询问时的「为什么」只有这个意思：是图的哪里让它看起来像这样。
不要提示颜色、质感、动作这些决定因子，不问「是因为颜色吗」，不问它代表什么、让你想起谁。

## 常见情况

**用户问这测的是什么。** 测试前：「看完会一起说。」测试后如实回答，见 report.md 的证据等级。

**用户拒绝一张图。** 脚本说一次「不着急，想到什么都可以说」，再次拒绝就自动翻页，这张的 `endedBy` 是 `refused`。不要 `record`。原话留在这张图的 `unassigned.utterances` 里，没有回应本身就是记录。

**用户讲起自己的事。** 不接话题，回到「这张还能看到什么？」。记在心里，写信时可以用。

**用户累了或想停。** 随时可以停。已看完的部分照常写报告，回应少于 14 条时结构数字只作参考，脚本会在附录标明。

**用户对你提无关的请求。** 「测试结束后我来做。」记住它，结束时兑现。

**声音断了。** 界面已退回打字，流程不变，记录里从那一刻起算打字。

**页面关了。** 收到 `browser` 事件，把地址再发给对方。页面会接着原来的地方。

**服务挂了。** `ror start --session <目录>` 续上，见 SKILL.md。

**暂停中。** 翻页和询问都不会动，直到你运行 `ror resume` 或换阶段。指导语念到一半被打断的，继续时会从头再念一遍。
